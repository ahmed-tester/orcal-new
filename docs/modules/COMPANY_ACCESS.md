# دليل نطاق الشركات والفروع

آخر مطابقة للكود المحلي: **2026-11-10**. نشر استخراج الخدمة المشتركة على السيرفر: **غير مؤكد**.

الرجوع إلى [الفهرس](../INDEX.md)، [الحضور](ATTENDANCE.md)، [التغييرات](../CHANGELOG.md)، [المشكلات](../KNOWN_ISSUES.md).

## الفكرة ومواقع التنفيذ

النطاق يحدد السجلات التي يمكن لاستعلام إرجاعها، أما صلاحيات العرض والإضافة والتعديل فتبقى في السياسات والصلاحيات. السماح بكل الفروع لا يساوي السماح بكل شركات النظام.

| المكون | المسؤولية |
| --- | --- |
| [User](../../app/Models/User.php) | تحديد السوبر أدمن والمالك والفروع والشركات المتاحة |
| [CompanyFormService::getAuthorizedCompanyIds](../../app/Services/CompanyFormService.php) | المدخل المشترك لجلب معرفات الشركات؛ يفوض إلى المستخدم الحالي أو المستخدم الممرر |
| [CompanyAccessScopeService::apply](../../app/Services/CompanyAccessScopeService.php) | تقييد Eloquent Builder بحسب المستخدم ونوع الموديل |
| [HasCompanyScope](../../app/Filament/Traits/HasCompanyScope.php) | يمرر `parent::getEloquentQuery()` إلى الخدمة؛ يبقى الاستدعاء في موارد Filament كما هو |
| [AttendanceSummaryService](../../app/Services/AttendanceSummaryService.php) | يطبق الخدمة على استعلام الموظفين للملخص والتفاصيل والتصدير والطباعة |

المنطق كان داخل الـTrait ثم استُخرج إلى الخدمة ليمكن استخدامه خارج الموارد. لا تضف `HasCompanyScope` إلى خدمة عادية لمجرد إعادة الاستخدام؛ استدعِ `CompanyAccessScopeService::apply($query)`.

## الشركات المتاحة من User

- السوبر أدمن: معرفات كل الشركات عند طلب القائمة.
- المالك: `getOwnedCompanyIds()` من سجلات `owners`؛ ليس كل شركات النظام.
- المستخدم العادي: شركة الموظف الأساسية، بالإضافة إلى شركات قسمه عبر `getAssignedCompanyIds()`، مع إزالة التكرار والقيم الفارغة.
- `branch_id` مشتق من علاقة موظف المستخدم، وليس مجرد قيمة مستقلة يجب افتراض وجودها في جدول users.
- `canAccessAllBranches()` يجيز ذلك للسوبر أدمن أو المالك أو صاحب صلاحية `view_any_branch` أو من ليس له فرع. هذا لا يلغي قائمة شركاته المصرح بها.

## ترتيب تطبيق النطاق الفعلي

| الحالة | النتيجة |
| --- | --- |
| لا مستخدم مسجل | لا نتائج (`1 = 0`) |
| سوبر أدمن | الاستعلام كما هو، مع بقاء فلاتر الوحدة وقيودها الأخرى |
| مورد Company مباشرة | المالك بشركاته المملوكة؛ غيره بالشركات المتاحة، والقائمة الفارغة لا تعيد نتائج |
| مالك في باقي الموديلات | شركة السجل المباشرة أو شركة الموظف ضمن المملوك؛ بلا قيد فرع |
| له فرع ولا يملك الوصول لكل الفروع | فرعه مباشرة، أو فرع الموظف إذا السجل مرتبط بموظف |
| مستخدم دون قيد فرع وله شركات متاحة | كل الفروع داخل شركاته المتاحة، عبر عمود الشركة أو علاقة الموظف |
| دون شركات متاحة ودون فرع مقيد | لا نتائج |

ترتيب الفرع الحالي يسبق فرع المستخدم العادي المعتمد على قائمة الشركات. لا تغيّر هذا الترتيب أو تستبدله بتقاطع جديد دون مراجعة أثره وموافقة المستخدم. الاستثناء الخاص بموديل Company يسبق قيد الفرع.

## أنواع الموديلات والاستثناءات

- إذا وجد `company_id` مباشرًا يستخدمه للمالك ومستخدم الشركة.
- إذا لم يوجد العمود ووجدت علاقة `employee()`، يستخدم `whereHas('employee')` لتقييد الشركة؛ هذه النقطة أصلحت تقييد جدول `attendance` الذي يحمل employee_id.
- قيد الفرع يستخدم `branch_id` المباشر أو `employee.branch_id`. موديل Branch نفسه يُقيد بـ`branches.id`.
- أقسام `departments` تبقى مرئية للمالك ومستخدم الشركة عند الشركة المباشرة، أو الربط عبر `companies`، أو `is_global = true`، وفق الاستثناء القديم المعتمد.
- الخدمة تفحص الأعمدة عبر Schema وتحتفظ بالنتيجة في ذاكرة العملية. لا تستخدمها كبديل عن صلاحية العملية.
- إذا الموديل لا يملك العمود المطلوب ولا علاقة الموظف، توجد مسارات تعيد الاستعلام كما هو. دعم الخدمة ليس ضمانًا لعزل أي موديل اعتباطي؛ افحص مخططه وعلاقاته قبل استعمالها. لم تشمل هذه المهمة تغيير تلك الحالات غير المرتبطة بالحضور.

## مواضع لا تُغطى تلقائيًا

استخدام الـTrait يقيّد `Resource::getEloquentQuery()`، ولا يحول نطاق الشركة إلى Global Scope في كل الموديلات. أي `Model::query()` مستقل أو إجراء مخصص أو خدمة تقرير يحتاج تطبيقًا صريحًا للقيد المناسب.

ملخص الحضور والتفاصيل والتصدير والطباعة أصبحوا يستخدمون الخدمة المشتركة. توجد خدمات أخرى لها تطبيقات نطاق مستقلة، ومنها [InstallmentSummaryService](../../app/Services/InstallmentSummaryService.php) و[AbstractReport](../../app/Services/Reports/Types/AbstractReport.php)؛ لا تفترض انتقالها إلى الخدمة أو اكتمال تدقيقها. راجع [SCOPE-001](../KNOWN_ISSUES.md#scope-001) عند توسيع التعميم.

## أمثلة الاستخدام

```php
// Resource: keep the existing trait.
use App\Filament\Traits\HasCompanyScope;

// Service: apply access first, then the user's filters.
$query = CompanyAccessScopeService::apply(Employee::query());
$query->whereIn('employees.company_id', $selectedCompanyIds);
```

المثال يفترض وجود imports المناسبة. الفلتر الثاني يضيّق نتائج الصلاحيات ولا يمنح وصولًا جديدًا. التأكد من موظف معين في الحضور يتم باستعلام مقيد ثم `whereKey(...)->exists()`، بدل مقارنة مستقلة قد تختلف عن القائمة.

## التحقق والنشر

الحالات المطلوبة لأي تعديل: مستخدم بدون فرع، فرع مقيد، صلاحية كل الفروع، شركات متعددة، قائمة شركات فارغة، مالك، سوبر أدمن، Company وBranch مباشرة، العلاقة عبر الموظف، والأقسام العامة/المشتركة؛ واختبارات صلاحية العملية منفصلة.

نتيجة الجولة السابقة 11 اختبارًا/89 تحققًا تاريخية. ملف التغطية الموسعة غير موجود حاليًا، كما هو موضح في [ATT-003](../KNOWN_ISSUES.md#att-003). لا تعتمد على تلك النتيجة كإثبات متاح للنسخة الحالية دون إعادة تجهيز وتشغيل الاختبارات.

تغيير الخدمة يؤثر في كل الموارد التي تستخدم الـTrait، وليس الحضور فقط. الخدمة ملف كلاس جديد؛ يجب رفعها مع الـTrait، وتشغيل `php artisan optimize:clear` بعد الرفع، والتحقق بحساب عادي إلى جانب السوبر أدمن. لم ينفذ المساعد نشرًا أو تعديل بيانات إنتاج.
