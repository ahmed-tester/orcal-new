# خطة: أوضاع استخراج كشف صندوق الأصول + اتجاه العرض والطباعة + قراءة الملاحظات

> **الحالة:** خطة مقترحة للمراجعة — لم يُنفّذ أي كود بعد.
> **المجال:** صفحة `/asset-fund-statement` + تصدير PDF `/asset-fund-statement/pdf`.
> **ملفات مرجعية:** `app/Filament/Pages/AssetFundStatement.php`، `app/Http/Controllers/AssetFundStatementController.php`، `resources/views/filament/pages/asset-fund-statement.blade.php`، `resources/views/pdf/asset-fund-statement.blade.php`.

---

## 1. الهدف

1. **اختيار الغرض من الاستخراج** قبل العرض/الطباعة: كشف كامل، كشف ضريبة فقط، كشف نسب واستقطاعات فقط، أو إجماليات فقط — بحيث يُخفى ما لا يخص الغرض من أعمدة وجداول وبطاقات.
2. **التحكم في اتجاه الاستخراج** (أفقي / عمودي) في الـ PDF وفي طباعة الشاشة، لأن الجدول الحالي (12 عموداً) مضغوط والملاحظات غير مقروءة.
3. **جعل الملاحظات مقروءة**: عمود أوسع مع التفاف النص، وإمكانية إظهار/إخفاء الملاحظات وطباعة الكشف بدونها عند الحاجة.

لا يوجد أي تغيير على قاعدة البيانات في هذه الخطة (لا أعمدة جديدة ولا migrations).

---

## 2. الوضع الحالي (نقطة البداية)

- الصفحة تعرض: بطاقات ملخص (5) + جدول سندات الإيداع (12 عموداً) + جدول سندات الصرف (9 أعمدة)، وتُبنى مباشرة داخل Blade بدون أي طبقة خدمات.
- `getSummaryProperty()` / `getDepositsSummaryProperty()` / `getWithdrawalsSummaryProperty()` في صفحة Filament، ونفس الحسابات مكرّرة داخل `AssetFundStatementController` (تكرار منطق يجب توحيده).
- الـ PDF ثابت على `A4-L` (أفقي) ولا يوجد أي خيار للمستخدم، وطباعة الشاشة (Ctrl+P) تخرج عمودية افتراضياً => الجدول يُقص.
- الملاحظات: خلية نص طويل بدون wrap مضبوط وبدون حد أدنى للعرض.
- لا يوجد فلتر «نوع الاستخراج» ولا «اتجاه الطباعة» في واجهة الفلاتر الحالية (الصندوق، من تاريخ، إلى تاريخ، نوع العمليات).

### 3.3 التنفيذ المقترح (بدون تكرار الشروط)

1. **Enum جديد** `app/Enums/AssetFundStatementMode.php`:
   ```php
   enum AssetFundStatementMode: string
   {
       case FULL = 'full';
       case TAX = 'tax';
       case DEDUCTIONS = 'deductions';
       case TOTALS = 'totals';

       public function label(): string;                 // من lang
       public function showsDepositColumn(string $key): bool;
       public function showsWithdrawalColumn(string $key): bool;
       public function showsCard(string $key): bool;
       public function hidesRows(): bool;               // true في TOTALS
   }
   ```
2. **Service جديد** `app/Services/AssetFundStatementService.php`:
   - `columnDefinitions(mode, section): array` — مصدر واحد لرؤوس الأعمدة + دالة إخراج القيمة لكل صف + دالة إجمالي التذييل.
   - `summary(vouchers): array` — نقل حسابات الملخص الحالية من الصفحة والـ Controller إليه.
   - عرض الأعمدة موحّد للشاشة والـ PDF (نفس المفاتيح، نفس التنسيق).
3. **Blade الشاشة + Blade الـ PDF**: بناء الجدولين بـ `@foreach ($columns as $column)` بدل 21 خلية مكتوبة يدوياً، مع نفس الـ Service. النتيجة: أي وضع جديد أو عمود جديد يُضاف في مكان واحد.
4. **الصفحة والـ Controller**: قراءة `report_mode`، تمريره للـ PDF في رابط التصدير، وإضافة عنوان الوضع في رأس الـ PDF (مثال: «كشف الضريبة — صندوق …»).

## 4. الميزة ٢: اتجاه العرض/الطباعة + الملاحظات

### 4.1 فلتر الاتجاه
حقل جديد `orientation` (أفقي / عمودي):

| القيمة | الاستخدام |
|---|---|
| `landscape` (افتراضي) | A4 عرضي — مناسب للكشف الكامل (12 عموداً) |
| `portrait` | A4 طولي — يُنصح به مع وضع `tax` أو `totals` فقط |

- **PDF:** يُبنى عبر `ExportPdfService::createMpdf(['format' => 'A4', 'orientation' => 'L'|'P', ...])` بدلاً من `'format' => 'A4-L'` الثابت، مع تصغير حجم الخط والهوامش تلقائياً في الوضع العمودي.
- **الشاشة/الطباعة:** إضافة `@media print` في Blade الصفحة:
  ```css
  @page { size: A4 landscape; margin: 8mm; }
  @media print { .af-stmt-card.filters, .af-btn { display: none !important; } }
  ```
  وربط الاتجاه المختار بمتغير CSS/Var لتبديل `@page` بين `landscape` و`portrait` حسب الاختيار.
- تنبيه واجهة (helperText): في الوضع العمودي مع الكشف الكامل تظهر رسالة «قد يكون الجدول مضغوطاً، استخدم الاتجاه الأفقي أو وضع الضريبة».

### 4.2 قراءة الملاحظات
1. عمود الملاحظات: عرض أدنى 180px، `white-space: normal; word-break: break-word; text-align: start;` بدلاً من قصّ النص.
2. خيار `show_notes` (إظهار الملاحظات في العرض والطباعة: نعم/لا، افتراضي نعم) — إخفاؤه يقلل الأعمدة عند الطباعة.
3. على الشاشة: `title` كامل للنص + حد 3 أسطر (`line-clamp`) لمنع ارتفاع الصفوف، مع إمكانية فتح نص الملاحظة كاملة عبر tooltip.
4. في الـ PDF: تُطبع الملاحظات كاملة (بدون قص) مع تكبير سطر الخلية.

## 6. خطة التنفيذ على مراحل (كل مرحلة قابلة للمراجعة منفصلة)

**المرحلة ١ — الطبقة الأساسية (بدون تغيير ظاهري):**
1. إنشاء الـ Enum والـ Service ونقل حسابات الملخص إليه.
2. ربط الصفحة والـ Controller بالـ Service.
3. شرط القبول: السلوك الحالي في وضع `full` مطابق تماماً لما هو الآن (أرقام وترتيب أعمدة).

**المرحلة ٢ — أوضاع الاستخراج:**
4. إضافة فلتر `report_mode` + بناء الجدولين من تعريفات الأعمدة (شاشة + PDF).
5. ضبط البطاقات حسب الوضع + عنوان الوضع في الـ PDF.
6. شرط القبول: كل وضع يعرض الأعمدة/البطاقات المذكورة في مصفوفة 3.2 فقط.

**المرحلة ٣ — الطباعة والملاحظات:**
7. فلتر `orientation` + `ExportPdfService` + `@media print`.
8. `show_notes` + تحسين عرض عمود الملاحظات على الشاشة والـ PDF.
9. شرط القبول: طباعة الشاشة تخرج أفقية افتراضياً بدون فلتر ولا أزرار، والملاحظات مقروءة كاملة في PDF.

## 7. التحقق والاختبار

1. `php -l` على كل ملف PHP مُعدّل/جديد + `php artisan view:clear`.
2. `vendor\bin\pint` على ملفات المرحلة (مع الحذر من إعادة تنسيق ملفات اللغة القديمة).
3. اختبار يدوي على صندوق فيه بيانات إيداع + صرف:
   - كل وضع × كل اتجاه × (مع/بدون ملاحظات).
   - التأكد من تطابق إجماليات التذييل والبطاقات مع مجموع الأعمدة الظاهرة.
4. اختبار Feature جديد `tests/Feature/AssetFundStatementTest.php`:
   - صحة حساب الملخص من الـ Service (ضريبة/استقطاع/رصيد).
   - أن وضع `tax` يتجاهل أعمدة النسب (تحقق من الـ HTML الناتج أو من `columnDefinitions`).
   - أن الـ PDF endpoint يرد 200 بنوع `application/pdf` للاتجاهين.
5. مقارنة PDF قبل/بعد في وضع `full` للتأكد من عدم وجود انحدار بصري.

## 8. المخاطر والقيود

- **الوضع العمودي مع الكشف الكامل:** 12 عموداً لا تكفي في A4 طولي؛ الحل: تحذير في الواجهة + تصغير تلقائي للخط + التشجيع على الوضع المناسب.
- **إعادة بناء الجدولين بـ loop:** أكبر جزء من الخطة من ناحية المخاطرة؛ تُعالَج أولاً في مرحلة ١ مع اختبار بصري لكل عمود.
- **تكرار المنطق الحالي:** صفحة Filament والـ Controller يحسبان الملخص مرتين؛ الـ Service ينهي هذا التكرار.
- **روابط قديمة:** أي رابط `pdf?fund_id=...` بدون الخيارات الجديدة يجب أن يعمل بافتراضيات `full` + `landscape` + `show_notes=1` (توافق خلفي كامل).
- **الصلاحيات:** تبقى كما هي (`view_asset_fund_statement` / `view_any_asset_fund` / مدير أو محاسب الصندوق).

## 9. أسئلة مفتوحة (تحتاج قراراً قبل التنفيذ)

1. في وضع **الإجماليات فقط**: تفضل بطاقات فقط بدون أي جدول، أم بطاقات + جدول صغير فيه (النوع / عدد السندات / الإجمالي)؟
2. كشف **النسب والاستقطاعات**: هل يشمل عمود الضريبة أيضاً (باعتبارها «استقطاعاً»)، أم بدون أي عمود ضريبة؟
3. كشف **الضريبة**: هل تريده سندات الإيداع فقط (كما في طلبك «كشف للضريبة لوحده»)، أم ضريبة الإيداع والسحب معاً في جدولين؟
4. اتجاه الطباعة الافتراضي: أفقي دائماً، أم نتذكّر آخر اختيار للمستخدم؟
5. هل تريد **كشف كل صندوق على حدة** (الوضع الحالي) أم لاحقاً كشفاً مجمّعاً لعدة صناديق في نفس الملف؟
