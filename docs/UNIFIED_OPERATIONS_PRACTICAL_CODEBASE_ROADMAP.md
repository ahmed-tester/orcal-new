# خطة التطوير العملية: تنفيذ «المحرك المالي الموحد» اعتماداً على كود Orcal القائم
### (تطوير ذكي ومستقر بأقل تعديل ممكن وبدون إعادة اختراع العجلة)

---

## 🎯 1. الاستراتيجية الهندسية: كيف نحقق المطلوب بالبناء على كودنا الحالي؟

بدلاً من بناء نظام جديد من الصفر أو كتابة مئات الملفات، نظام **Orcal** يحتوي بالفعل على **80% من البنية المطلوبة**:
* لدينا شاشة ونموذج **`ServiceTransactions`** متقدمة جداً ومربوطة بالشركات والموظفين والخدمات.
* لدينا **`CodeGeneratorService`** يولد أكواد العمليات التسلسلية `SRV-C{company_id}-{seq}`.
* لدينا **`Invoices`** و **`TreasuryTransactions`** و **`Debts`** و **`Tasks`**.

كل ما نحتاجه هو **«طبقة ربط وأتمتة خفيفة» (Orchestration Layer)** تربط هذه الأجزاء ببعضها عند حدوث حركات في المعاملة.

```
[شاشة ServiceTransaction الحالية]
           │
           ├─── (1) عند الحفظ ──────────► إنشاء تلقائي لسجل في Invoices (بنفس الرقم والمبلغ)
           │
           ├─── (2) إذا فيه متبقي ──────► إنشاء تلقائي لسجل في Debts (دين على العميل لمتابعته)
           │
           ├─── (3) كاش في جيب الموظف ──► توليد باركود تسليم للخزينة (QR Code + رقم المعاملة)
           │                                      │
           │                                      ▼
           │                             [شاشة الخزينة الحالية Treasury]
           │                             أمين الخزنة يمسح الباركود / يدخل الرقم
           │                             ← تنشأ حركة INCOMING تلقائياً وتسقط العهدة عن الموظف
           │
           └─── (4) نقص إيصال سداد ─────► ينشئ النظام مهمة في Tasks لمسؤول السداد
```

## 🛠️ 2. التعديلات المحددة على الملفات الحالية (Minimal Diffs)

### 2.1 نموذج ومورد معاملات الخدمات (`ServiceTransaction`)
* **الملفات المستهدفة:**
  - `app/Models/ServiceTransaction.php`
  - `app/Filament/Resources/ServiceTransactions/Schemas/ServiceTransactionForm.php`
  - `app/Filament/Resources/ServiceTransactions/Tables/ServiceTransactionsTable.php`
* **الإضافات المطلوبة فقط:**
  1. إضافة حقل `cost_bearer` (من يتحمل التكلفة: عميل دفع / دين على العميل / على المكتب / مشترك).
  2. إضافة حقل `gov_fee_amount` (مبلغ الرسوم الحكومية للسداد) وحقل `office_fee_amount` (مبلغ أتعاب المكتب للإيداع)، ويتم ملؤهما تلقائياً من موديل `Service` (`default_gov_fee` و `price`).
  3. إضافة حقلين للمرفقات: `gov_receipt_path` (إيصال سداد الرسوم) و `bank_deposit_receipt_path` (إشعار الإيداع البنكي).
  4. تحديث الحالات التشغيلية لتشمل حالات المخطط الأساسية (`pending_custody`, `in_treasury`, `under_settlement`, `completed`).

### 2.2 الأتمتة عبر المراقب (`ServiceTransactionObserver`)
* **الملف:** `app/Observers/ServiceTransactionObserver.php`
* **السلوك:**
  - `created`:
    * إنشاء فاتورة تلقائية في جدول `invoices`.
    * إذا كان هناك مبلغ متبقٍ (`remaining_amount > 0`) أو تم اختيار «دين على العميل»، يتم إنشاء سجل دين تلقائي في جدول `debts`.
  - `updating`:
    * عند اكتمال السداد وإرفاق الإيصالات، تتحول المعاملة تلقائياً إلى «مكتملة ومطابقة».
    * إذا تأخر إرفاق إيصال السداد، إنشاء مهمة في جدول `tasks` للموظف المنفذ.

### 2.3 تسليم الكاش للخزينة بالباركود (`TreasuryBarcodeHandoverAction`)
* **الملف:** Action بسيط في شاشة الخزينة `TreasuryTransactionsTable.php` ومودال تفاعلي:
  1. الموظف في شاشة المعاملة يملك زراً: **«عرض باركود التسليم»** يظهر QR Code يحتوي: `{"srv": "SRV-C1-0025", "amount": 1500}`.
  2. أمين الخزنة في شاشة الخزينة يملك زراً: **«استلام عهدة نقدية»**؛ يمسح الباركود أو يكتب رقم المعاملة، فيستعرض النظام المعاملة فوراً، وبضغطة زر **«تأكيد الاستلام»**:
     - يُنشئ النظام حركة خزينة واردة `TreasuryTransaction` بمبلغ الكاش.
     - يُحدث حالة المعاملة إلى `in_treasury`.
     - تسقط العهدة عن الموظف.

## 🚫 3. حدود النظام وتفادي التوسع العشوائي (ما لن نقوم به حفاظاً على النظام)

1. **الرواتب (`PayrollRecords`):** لا يتم دمجها في شاشة الخدمات؛ نظام المسيرات الحالي متطور جداً ومحكم محاسبياً وله سندات صرفه وحركاته العكسية الخاصة.
2. **الصناديق المالية (`AssetFunds`, `LoanFunds`, `RoscaFunds`):** تظل مستقلة تماماً كما أكد المخطط صراحة.
3. **العقود والإيجارات (`ContractVouchers`):** تبقى في شاشتها المتخصصة.
4. **الربط الخارجي مع البنوك والجوازات:** لا يوجد ربط API خارجي؛ التوثيق يعتمد على قيام الموظف برفع صور وملفات PDF للإيصالات والإشعارات البنكية كما هو معتاد في كافة المكاتب.
