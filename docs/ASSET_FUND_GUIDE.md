> **تاريخ التوثيق:** نوفمبر 2026

## 1. الفكرة باختصار (ما هو صندوق الأصول؟)

**صندوق الأصول** حساب مستقل داخل النظام (ليس الخزينة العامة) تُجمَّع فيه مبالغ محتجزة إلى حين الحاجة إليها، مثل:

- فائض مبيعات أو مبالغ مخصّصة لمؤسسة/إدارة معيّنة.
- مبالغ الزكاة والضريبة المحجوزة عند السداد.
- أي مبلغ «مودَع» لغرض محدد وليس للتداول اليومي.

الحركة المالية في الصندوق من نوعين فقط:

| النوع | الأثر على الرصيد | الشاشة/الحقل |
| :--- | :--- | :--- |
| **سند إيداع** (`deposit`) | **يزيد** الرصيد | نوع السند = إيداع |
| **سند سحب** (`withdrawal`) | **ينقص** الرصيد | نوع السند = سحب |

الرصيد الحالي لأي صندوق = `إجمالي الإيداعات − إجمالي السحوبات` (يُحسب آلياً ولا يُدخَل يدوياً).

> **تمييز مهم:** الصندوق **غير مرتبط بمنشأة** كسكوب، لكن كل سند قد يُربط بمنشأة اختيارياً عند اختيار «ربط بمنشأة» لتوضيح مصدر/وجهة المبلغ.

## 3. بنية البيانات

```
asset_funds 1 ──── * asset_fund_vouchers 1 ──── * asset_fund_voucher_items
      │                        │
   مدير/محاسب            company? (اختياري عند «ربط بمنشأة»)
   (موظفون)                    party_name? (عند «إدخال حر»)
```

### 3.1 جدول `asset_funds` — الصناديق

| العمود | ملاحظات |
| :--- | :--- |
| `fund_number` | فريد، يُولَّد آلياً عبر `CodeGeneratorService` ببادئة `AF` |
| `fund_name` | مطلوب |
| `established_date` | تاريخ الإنشاء (افتراضياً اليوم) |
| `description` | نبذة تعريفية عن الصندوق |
| `rules_and_conditions` | شروط الإيداع والسحب |
| `manager_employee_id` / `manager_name` | مدير الصندوق: يُختار من **الموظفين السعوديين**، ويُخزَّن اسمه تلقائياً |
| `accountant_employee_id` / `accountant_name` | محاسب الصندوق (اختياري)، نفس القاعدة |
| `status` | `active` (نشط) / `closed` (مغلق) — الافتراضي `active` |
| `notes` | ملاحظات حرة |
| `created_by` | المستخدم المُنشئ |

**خصائص محسوبة (Accessors) على الموديل:**

- `balance` = `total_deposits − total_withdrawals`
- `total_deposits` = مجموع `total_amount` للسندات من نوع إيداع
- `total_withdrawals` = مجموع `total_amount` للسندات من نوع سحب

### 3.2 جدول `asset_fund_vouchers` — السندات

| العمود | ملاحظات |
| :--- | :--- |
| `asset_fund_id` | الصندوق التابع له السند (حذف الصندوق يحذف سنداته) |
| `voucher_number` | فريد، يُولَّد آلياً ببادئة `DEP` للإيداع و `WDR` للسحب |
| `type` | `deposit` / `withdrawal` |
| `voucher_date` | تاريخ السند (افتراضياً اليوم) |
| `total_amount` | **قراءة فقط** — مجموع صفوف التفاصيل |
| `source_type` | `company` (ربط بمنشأة) / `free` (إدخال حر) |
| `company_id` | يُستخدم فقط عند `company` |
| `party_name` | يُستخدم فقط عند `free` |
| `notes` | ملاحظات وبيان المبلغ |
| `created_by` | مُسجِّل السند |

### 3.3 جدول `asset_fund_voucher_items` — تفاصيل المبلغ

| العمود | ملاحظات |
| :--- | :--- |
| `description` | البيان/الوصف |
| `percentage` | نسبة مئوية (0–100) — **بيانية فقط، لا تدخل في الحساب** |
| `sub_total` | المبلغ الأساسي للبند |
| `extra_1` / `extra_2` | إضافات («أخرى 1» و«أخرى 2») |
| `row_total` | محسوب = `sub_total + extra_1 + extra_2` |
| `sort_order` | ترتيب البند داخل السند |

## 4. شاشة «صناديق الأصول» (`/asset-funds`)

### 4.1 جدول العرض

| العمود | الوصف |
| :--- | :--- |
| رقم الصندوق | شارة (badge) بلون مميز، قابل للبحث والفرز |
| اسم الصندوق | قابل للبحث والفرز |
| تاريخ الإنشاء | ميلادي |
| مدير الصندوق | يُعرض من علاقة الموظف أولاً |
| **الرصيد الحالي** | أخضر إن كان ≥ 0، أحمر إن كان سالباً |
| عدد السندات | شارة |
| الحالة | نشط/مغلق |

- الترتيب الافتراضي: الأحدث إنشاءً أولاً.
- الإجراءات لكل صف: **تعديل** و**حذف** (داخل قائمة إجراءات).
- حذف جماعي متاح.

### 4.2 نموذج الإنشاء/التعديل

يتكون من قسمين:

1. **بيانات الصندوق الأساسية:** رقم الصندوق (يظهر بعد الحفظ فقط) — اسم الصندوق — تاريخ الإنشاء — الحالة — نبذة تعريفية.
2. **إدارة الصندوق والمسؤوليات:** مدير الصندوق (موظف سعودي) — محاسب الصندوق (موظف سعودي) — شروط الإيداع والسحب — ملاحظات.

> عند اختيار المدير أو المحاسب يُحفظ اسمه تلقائياً في `manager_name` / `accountant_name` عند كل حفظ (حدث `saving` في الموديل).

## 5. شاشة «سندات الإيداع والسحب» (`/asset-fund-vouchers`)

### 5.1 جدول العرض

رقم السند — الصندوق — نوع السند (شارة) — التاريخ — المبلغ (أخضر للإيداع / أحمر للسحب) — الطرف/الجهة — الملاحظات.

**الفلاتر:** نوع السند، الصندوق. الترتيب الافتراضي: تاريخ السند تنازلياً.

### 5.2 نموذج السند (ثلاثة أقسام)

**١) بيانات السند الأساسية**

- رقم السند (بعد الحفظ فقط).
- الصندوق: قائمة **الصناديق النشطة فقط** (`status = active`).
- نوع السند: إيداع / سحب.
- تاريخ السند.

**٢) مصدر / وجهة المبلغ**

- نوع المصدر/الوجهة:
  - **ربط بمنشأة** ← يظهر حقل «المنشأة» (إلزامي) ويُخفى «اسم الطرف».
  - **إدخال حر** ← يظهر «اسم الطرف/الجهة» (إلزامي) ويُخفى حقل المنشأة.
- ملاحظات: توضّح مصدر المبلغ أو وجهته.

قاعدة التنظيف: عند اختيار `free` يُصفَّر `company_id`، وعند `company` يُصفَّر `party_name` (في النموذج وفي حدث `saving` بالموديل).

**٣) تفاصيل المبلغ (جدول بنود)**

| الحقل | الحساب |
| :--- | :--- |
| البيان/الوصف | نص حر |
| النسبة % | 0–100 (توضيحية) |
| الإجمالي (`sub_total`) | إدخال يدوي |
| أخرى 1 / أخرى 2 | إدخال يدوي |
| **المجموع (`row_total`)** | آلي = `sub_total + extra_1 + extra_2` |
| **إجمالي المبلغ (`total_amount`)** | آلي = مجموع صفوف البنود، وقراءة فقط |

الحساب يتم لحظياً في الواجهة (`live`) عبر دوال `recalcRow()` / `recalcTotal()` في `AssetFundVoucherForm`، ويُعاد الحساب عند إضافة أو حذف بند.

> **مثال:** بند بـ 1,000 + أخرى 1 = 100 + أخرى 2 = 50 ← المجموع 1,150. وبندان آخران 500 و250 ← إجمالي السند = 1,900 ر.س.

## 6. شاشة «كشف حركة الصندوق» (`/asset-fund-statement`)

صفحة Filament مخصّصة (Livewire) بعرض كامل.

### 6.1 الفلاتر (تحديث فوري `wire:model.live`)

| الفلتر | الأثر |
| :--- | :--- |
| الصندوق | إلزامي لعرض أي نتيجة |
| من تاريخ | `voucher_date >= من` |
| إلى تاريخ | `voucher_date <= إلى` |
| نوع العمليات | الكل / الواردات فقط / المصروفات فقط |

### 6.2 النتائج

- **ثلاث بطاقات ملخص:** إجمالي الواردات — إجمالي المصروفات — الرصيد الصافي (للفترة المفلترة فقط).
- **جدول الحركات:** # — رقم السند — التاريخ — النوع — الطرف/الجهة — الملاحظات — المبلغ (+/−).
- الحركات مرتبة تصاعدياً بتاريخ السند.
- عند عدم وجود صندوق محدد تظهر رسالة «اختر صندوقاً»، وعند عدم وجود حركات تظهر «لا توجد حركات مطابقة».

### 6.3 الطباعة / PDF

زر **«طباعة / PDF»** يفتح `/asset-fund-statement/pdf` بنفس الفلاتر في تاب جديد.

- القالب: `resources/views/pdf/asset-fund-statement.blade.php`
- المحرك: **mPDF** بخط `dejavusans` مع `autoArabic` و`rtl` وحذف BOM من HTML.
- يحتوي الكشف المطبوع على: ترويسة الصندوق (الاسم/الرقم/تاريخ الإنشاء/المدير/المحاسب)، شريط الفلاتر وتاريخ الاستخراج، جدول الحركات، ثم جدول الملخص.
- ملف PDF يُعرض inline باسم `asset-fund-statement-{fund_number}.pdf`.

| `delete_asset_fund` | حذف صندوق |
| `view_any_asset_fund_voucher` | استعراض السندات |
| `create_asset_fund_voucher` | تسجيل سند إيداع/سحب |
| `update_asset_fund_voucher` | تعديل سند |
| `delete_asset_fund_voucher` | حذف سند |
| `view_asset_fund_statement` | استعراض كشف الحركة |

تُمنَح من شاشة **الأدوار** (`Roles`) ضمن مجموعة صلاحيات المالية العامة والخدمات.

### 7.2 السياسات (Policies)

`AssetFundPolicy` و`AssetFundVoucherPolicy` تستخدمان `HasSuperAdminBypass`:

- **المالك / السوبر أدمن:** وصول كامل تلقائي.
- **مدير الصندوق أو محاسبه** (عبر `employee_id` للمستخدم): يرى ويعدّل صندوقه وسنداته وكشفه **تلقائياً دون صلاحية صريحة**.
- غير ذلك: يعتمد على صلاحيات Spatie أعلاه.

### 7.3 ملاحظة أمنية للكشف

صفحة الكشف تفلتر قائمة الصناديق للمستخدم غير المصرّح له لتعرض صناديقه فقط (مدير/محاسب)، ومسار PDF يعيد **403** برسالة عربية لمن لا يملك حق الوصول.

## 8. سيناريو استخدام كامل (خطوة بخطوة)

1. **إنشاء الصندوق:** صناديق الأصول ← «جديد» ← أدخل الاسم وتاريخ الإنشاء والمدير والمحاسب والشروط ← حفظ. يُولَّد رقم مثل `AF-0001`.
2. **تسجيل إيداع:** سندات الإيداع والسحب ← «جديد» ← اختر الصندوق، النوع = **إيداع**، التاريخ، المصدر (منشأة أو حر + اسم الطرف) ← أضف بنود المبلغ ← حفظ. المبلغ الإجمالي يُحسب آلياً.
3. **تسجيل سحب:** نفس الخطوات مع النوع = **سحب**؛ ينقص الرصيد تلقائياً.
4. **متابعة الرصيد:** عمود «الرصيد الحالي» في قائمة الصناديق يعكس فوراً نتيجة الإيداعات والسحوبات.
5. **استخراج كشف:** كشف حركة الصندوق ← اختر الصندوق والفترة والنوع ← استعرض البطاقات والجدول ← «طباعة / PDF».

## 11. ملاحظات وحدود معروفة (مهمة قبل التطوير التالي)

| # | الملاحظة | الأثر |
| :--- | :--- | :--- |
| 1 | **لا يوجد تحقق من كفاية الرصيد عند السحب** — يمكن أن يصبح الرصيد سالباً (يظهر بالأحمر). | قد يُطلب منع السحب فوق الرصيد برسالة عربية. |
| 2 | **حذف السندات متاح** (فردي وجماعي) ويُحدّث الرصيد تلقائياً لأن الرصيد محسوب لا مُخزَّن. | لا يوجد قيد عكسي أو سجل تدقيق للحركات المحذوفة. |
| 3 | **نسبة البند (`percentage`) لا تدخل في الحساب**؛ الحساب يعتمد على `sub_total + extra_1 + extra_2`. | إن أردت حساباً نسبياً (مثل نسبة من مبلغ أساسي) يحتاج تعديل منطق `recalcRow()`. |
| 4 | **الرصيد يُحسب باستعلامين لكل صف** في جدول الصناديق (N+1). | مقبول للأعداد الصغيرة؛ يُفضَّل تجميعه بـ `withSum` عند توسّع البيانات. |
| 5 | **كشف الحركة لا يعرض رصيداً افتتاحياً ولا رصيداً متحركاً**؛ الملخص يخص الفترة المفلترة فقط. | إضافة «رصيد افتتاحي/ختامي» تتطلب استعلاماً قبل `date_from`. |
| 6 | **لا توجد طباعة لسند الإيداع/السحب** — الطباعة متاحة للكشف فقط. | يمكن إضافة قالب سند لاحقاً على نمط الخزينة. |
| 7 | **لا يوجد تبويب حركات داخل شاشة الصندوق** (لا RelationManager ولا صفحة عرض)؛ الحركات تُدار من شاشة السندات. | تجربة المستخدم تعتمد على شاشة السندات + الكشف. |
| 8 | **التواريخ ميلادية فقط** (لا `HasHijriDates` على هذه الوحدة). | إضافة الهجري تتطلب تفعيل الـ trait وحقول metadata. |
| 9 | **مسار مؤقت لتوليد الصلاحيات** ما زال موجوداً في `routes/web.php` (`/seed-asset-fund-permissions`). | يُفضَّل حذفه بعد التأكد من زرع الصلاحيات على السيرفر. |
| 10 | الحذف الفعلي للصندوق يحذف كل سنداته (`cascadeOnDelete`). | لا يوجد أرشفة/تعطيل إجباري قبل الحذف (يمكن استخدام حالة «مغلق»). |

## 12. خطوات مقترحة لاحقاً (اختياري)

1. منع السحب الذي يتجاوز الرصيد المتاح (تحقق في طبقة Service + رسالة عربية + تعطيل الحفظ).
2. استخراج منطق حساب البنود والإجمالي إلى `AssetFundVoucherService` تطبيقاً لقاعدة «لا حسابات مالية داخل الصفحات».
3. إضافة رصيد افتتاحي ورصيد متحرك لكشف الحركة (شاشة + PDF).
4. قالب طباعة لسند الإيداع/السحب مع تفقيط المبلغ (`TafqeetService`).
5. تحسين أداء عمود الرصيد باستخدام `withSum` أو أعمدة cache.
6. حذف المسار المؤقت `/seed-asset-fund-permissions`.
